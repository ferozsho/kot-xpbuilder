{# Custom tail JS for Kot XPBuilder Superset stacks. Superset 6.1 native filters STAGE a "Clear all" (the select inputs empty) but only commit the clear when "Apply" is clicked — so charts kept their old values and the "Clear all" button looked broken. Auto-clicking Apply is unreliable (Apply can go stale/disabled), so this hook reaches the app's Redux store directly (via the React fiber tree) and dispatches UPDATE_DATA_MASK (value null) for every native filter: this clears the APPLIED data mask, re-queries all charts and collapses the filter chips in one go. #} {# Brand logo link fixer: clicking the navbar brand logo returns to the linked Moodle site instead of the Superset home page. * A per-launch `?xp_return=` wins — the Moodle connector's sso.php appends it when it opens the console, so leaving Superset lands back on the exact Moodle page that launched it (the dashboard the user was viewing). * XPBUILDER_BRAND_URL is the configured fallback (point it at the Moodle dashboard list) for arrivals that carry no launcher context. `xp_return` is honoured only when it points at XPBUILDER_MOODLE_URL, so the logo cannot be turned into an open redirect. The logo is a React-rendered anchor, so re-apply on an interval in case the app re-renders the navbar. #} {# Embedded-dashboard height reporter. Inside the connector's embed.php the dashboard runs in a CROSS-ORIGIN iframe, so the host page cannot measure it: the embed was pinned to `calc(100vh - 150px)`, the dashboard's own content is usually taller, and the user ended up with TWO scrollbars — the page's and the dashboard's. The app therefore reports its own content height and embed.php sizes the host iframe from it, so the dashboard is rendered at full height and the only scrollbar is the page's. Skipped when the app is not framed (an admin browsing Superset directly). `scrollHeight` is read from both and because which one carries the overflow depends on the theme; a 4px dead-band stops the growth from oscillating while the dashboard re-lays out. #} {# Rebranding: the compiled frontend still ships upstream wording in menus, tooltips and empty states. `APP_NAME` fixes the tab title and the navbar brand; this walks the RENDERED TEXT and rewrites the remaining strings, so nothing waits on a frontend rebuild. Text nodes and user-visible attributes only — never inputs, code blocks or URLs. #} {# Embedded dashboards are read-only. A guest-token viewer has NO Superset session, so the "editing" entries in a chart's ⋮ menu are dead ends: "Edit chart" pushes /explore/, a server-rendered page that cannot authenticate a guest token, and the dashboard is replaced by a blank frame. "View query" hands a report reader raw SQL, and "Share" builds links the viewer cannot open. The frontend itself now hides them (SliceHeader / SliceHeaderControls gate the explore affordance on isEmbedded()) — but that only lands on the next frontend build, so this keeps already-deployed images clean. It is a no-op once the app stops rendering those items, and it only ever runs inside a frame (an admin browsing the console directly is unaffected). #}
